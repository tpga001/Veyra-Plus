# 后续计划

建仓不自动开始以下产品改动，按用户下一次确认的范围推进。

1. **偶发卡顿诊断**：记录帧序号、PTS、requested/detected/final reset 原因，定位反复重置来源，保留有效 seek/切源/长间隔重置。
2. **补帧时限与排队**：对齐源到达、GPU 完成、计划及实际显示时间，区分算力、排队、时钟和生成帧过期问题。
3. **浏览器源节奏**：核对约 30 FPS 视频与 60 FPS 捕获是否产生重复内容，再减少无效增强；24x2 不等于 60 个独立画面。
4. **算力余量对照**：需要时比较 NR 1080p、900p 与关闭 NR，其他参数保持一致，保留用户画质选择。
5. **实际显示验收**：本地/浏览器分别做同源、同窗口、同屏幕的重复长片测试，比较 1% Low、P99、长帧次数、最大间隔与延迟。优先后台检查，最终显示验收再要求可见播放。
6. **功能与上游同步**：ASSRT 真人账户验收、后续在线弹幕和原始视频帧研究；审查上游更新后按需合并，不将整个版本升级混入单个修复。

现有日志线索不是已确认根因。降低内部尺寸也不能保证解决所有偶发长帧。
